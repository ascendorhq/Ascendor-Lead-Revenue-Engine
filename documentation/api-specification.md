
# Ascendor API Specification

## 1. Overview

This document defines the HTTP API endpoints and request/response
formats for the Ascendor Lead-to-Revenue Engine MVP.

The API is implemented using Flask.

## 2. Base Configuration

- **Development Host:** `http://localhost:5000`
- **API Version:** v1
- **Content Type:** `application/json`

## 3. Health Check API

### Endpoint

`GET /health`

### Purpose

Verify that the Ascendor API is responding.

### Successful Response

HTTP 200 OK

```json
{
  "service": "Ascendor Lead-to-Revenue Engine",
  "status": "healthy",
  "version": "0.1.0"
}
```

This endpoint checks API availability.
It does not verify database connectivity.

## 4. Lead Intake API

### Endpoint

`POST /api/v1/leads`

### Purpose

Receive, validate, normalize, and persist incoming business leads.

### Request Headers

```http
Content-Type: application/json
```

### Request Body

```json
{
  "name": "John Smith",
  "email": "john@example.com",
  "phone": "+639123456789",
  "company": "Example Company",
  "source": "website"
}
```

### Request Fields

| Field | Type | Required | Description |
|---|---|---|---|
| name | String | Yes | Lead's full name |
| email | String | Yes | Lead's email address |
| phone | String | No | Lead's phone number |
| company | String | No | Lead's company name |
| source | String | No | Lead acquisition source |

### Validation Rules

- Name must be a non-empty string.
- Name must not exceed 150 characters.
- Email must be a non-empty string.
- Email must not exceed 254 characters.
- Email must follow the application's email validation format.
- Phone must be a string when provided and must not exceed 30 characters.
- Company must be a string when provided and must not exceed 150 characters.
- Source must be a string when provided and must not exceed 100 characters.
- Invalid submissions shall be rejected.

### Data Normalization

Email addresses are normalized by:

- Removing surrounding whitespace.
- Converting characters to lowercase.

## 5. Successful Lead Response

### HTTP Status

`201 Created`

### Response Body

```json
{
  "success": true,
  "message": "Lead created successfully",
  "lead": {
    "id": "generated-uuid",
    "full_name": "John Smith",
    "email": "john@example.com",
    "created_at": "2026-11-07T12:00:00+00:00"
  }
}
```

### Response Fields

| Field | Type | Description |
|---|---|---|
| success | Boolean | Indicates successful processing |
| message | String | Operation result |
| lead.id | String | Generated lead UUID |
| lead.full_name | String | Stored lead name |
| lead.email | String | Normalized email address |
| lead.created_at | String | Lead creation timestamp in ISO 8601 format |

The actual timestamp is generated by PostgreSQL.

## 6. Error Responses

### 6.1 Invalid JSON Request

HTTP 400 Bad Request

```json
{
  "success": false,
  "message": "Invalid JSON request body"
}
```

### 6.2 Validation Error

HTTP 400 Bad Request

```json
{
  "success": false,
  "message": "Email is required"
}
```

The message depends on the validation failure.

### 6.3 Duplicate Lead

HTTP 409 Conflict

```json
{
  "success": false,
  "message": "A lead with this email already exists"
}
```

Duplicate detection is enforced through email uniqueness
in the database.

### 6.4 Database Error

HTTP 500 Internal Server Error

```json
{
  "success": false,
  "message": "Database operation failed"
}
```

Internal database error details are logged
rather than returned to the API client.

## 7. Lead Processing Flow

The API follows this processing sequence:

1. Receive the HTTP request.
2. Parse the JSON request body.
3. Validate lead information.
4. Normalize the email address.
5. Insert the lead into PostgreSQL.
6. Return the appropriate HTTP response.
7. Log database errors when applicable.

## 8. Current API Limitations

- API authentication is not implemented.
- Rate limiting is not implemented.
- Request size restrictions are not explicitly configured.
- Database connectivity is not checked by the health endpoint.
- API access is intended for controlled development.
- Production HTTPS and security controls are not yet implemented.
